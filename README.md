# 电视固件工坊

[打开在线选配](https://huhao0208.github.io/tcl-firmware-builder/) · [刷机说明](docs/FLASHING.md) · [常见问题](#常见问题) · [构建边界](PRODUCT.md) · [第三方来源](SOURCES.md) · [验证记录](docs/VERIFICATION.md)

在网页上为 **TCL T800T11（`tc8000_ay30a2` 主板 / Android 11 / V178 底包）** 勾选想要的定制项，用你自己的 GitHub 账号提交构建请求，Actions 自动生成完整的 U 盘刷机镜像（解压后约 2.9 GB）。全程不需要在电脑安装工具，也不需要给网页任何令牌。

## 先确认：这台电视适用吗

| 检查项 | 通过标准 |
| --- | --- |
| 电视型号 | TCL T800T11 |
| 固件版本（电视 设置 → 关于/系统信息） | 类似 `V8-T800T11-LF1V178.xxxxx`（V178 底包） |
| 能接受的代价 | 刷机**可能清空应用、账号和设置**；刷机前必须留好恢复用原包 |

任何一条不确定就不要刷。本仓库只针对上述主板与底包制作并由维护者在同一台电视上验证；外壳型号相同不代表主板与分区相同，不支持其他板型、版本或 Recovery `update.zip`。

## 三步拿到刷机包

1. **选配**：打开[在线选配页](https://huhao0208.github.io/tcl-firmware-builder/)勾选组件（每项含义见下面速查表），页面生成一份构建请求。
2. **提交**：点击“在 GitHub 提交构建”，用**自己的 GitHub 账号**在新请求页确认创建。出于防滥用考虑，构建仅由带 `build-request` 标签的请求触发，该标签只有本仓库协作者能够保留——公开提交的 Issue 不会启动构建。进度看请求里的机器人评论或网页的任务查询，不虚构百分比。
3. **下载与刷入**：完成后从 Release 下载 ZIP → 核对 SHA-256 → 解压 → 按[刷机说明](docs/FLASHING.md)准备 U 盘强刷。**ZIP 是压缩包，不能改后缀当 IMG。**

## 组件速查

| 选项 | 勾上会发生什么 |
| --- | --- |
| Magisk Root | 底包刷入 Magisk 27 获得 Root；下面所有定制项都依赖它 |
| 原包模式（不 Root） | 重新刷一个未修改的原厂 V178；此时任何定制项都不可选 |
| Aerial 桌面 | 装入私人签名稳定版 Aerial（wb.11）并设为默认桌面；原桌面系统包保留，仅禁用其两个桌面入口 |
| 广告管理 | 装入 CastGuard，屏蔽投屏广告域名（默认 3 条公开规则，不含任何家庭个性化配置） |
| 购物键 | 装入桥接应用，遥控器“直播购物”键改为打开你在 Aerial 里指定的已装应用（依赖 Aerial 桌面） |
| 七项预装精简 | 对当前用户移除安全卫士、玩机技巧、视频通话、应用商店、搜索、艺术画框、天气预报的入口；系统分区 APK 保留，可按包名单独恢复 |
| 安装策略 | `vendor` 保持原厂规则；`home` / `home_adb` 允许第三方桌面与 ADB 安装（不关闭 SELinux 或签名校验）；厂商云控可能覆盖 |

## 风险速读

- 所有自定义组合都是**未实刷候选**：云端校验通过 ≠ 你的电视一定能启动。
- U 盘强刷写入整盘镜像，中途断电可能变砖；固件自带的升级配置**可能清空应用、账号和设置**。
- 刷机前必须在电脑/NAS 留存一份完整的原救砖包，恢复方法见[刷机说明](docs/FLASHING.md)。
- “精简”只是移除当前用户的入口，不是物理删除系统分区内容。
- 首次启动需要安装所选组件，可能耗时数分钟属正常。

## 常见问题

**下载的 ZIP 只有 1.8 GB，是不是没下完？**
正常。ZIP 是压缩传输格式（约 1.9 GB），解压后的完整镜像约 2.9 GB。判断下载是否完整只看字节数和 SHA-256（对照 Release 页与 ZIP 内 `SHA256SUMS`），不看体积。

**我提交了 Issue，为什么没有反应？**
出于防滥用设计，公开请求不会启动构建（见上文第 2 步）。你的 Issue 不会自动运行；只有协作者的请求或维护者手动触发才会构建。

**构建失败了怎么办？**
看请求里机器人评论给出的具体原因。最常见的是配置未通过校验——回到网页改正后重新提交；已发布的其他下载不受影响。

**我的电视型号差不多，能刷吗？**
不能。仅支持 TCL T800T11 / `tc8000_ay30a2` / V178；型号相近或底包不同都不在验证范围内，不要尝试。

**能把 ZIP 改名成 .img 直接刷吗？**
不行。必须解压出完整镜像，文件名保持 `V8-T800T11-LF1V178.001228_notfull.img` 放在 U 盘根目录。

**刷失败或变砖怎么办？**
用留存的原救砖包按同一机身键流程恢复，步骤见[刷机说明](docs/FLASHING.md)。所以刷机前留好原包是硬性前提。

**精简掉的七项应用还能恢复吗？**
能。精简只是对当前用户移除入口，系统 APK 都还在。通过 adb 执行 `cmd package install-existing --user 0 <包名>` 可单项恢复（包名清单见 `catalog/inputs.json` 与成品 BUILD.json）；原桌面的两个入口同理可用 `pm enable` 恢复。

**为什么不直接从系统分区里删掉这些应用和原桌面？**
物理删除不会多出任何可用空间（系统分区只读且大小固定），却必须修改 super 分区并重建整条校验链（dm-verity/vbmeta），失去本项目"除 boot 外逐字节不变"的安全论证，还引入 OTA 兼容与救砖风险；删掉原桌面后一旦第三方桌面起不来，电视将没有任何可用 HOME。当前方案每一步都可单项撤销，是刻意选择的最小风险点。

**会动我电视里的数据吗？**
构建本身只发生在 GitHub，不会碰你的电视；刷入属于整盘强刷，可能清空数据，详见上文“风险速读”。

## 构建与校验

静态网页直接部署在 GitHub Pages，无服务器、无网页 PAT。Issue 创建时的配置快照经有限枚举校验，可信默认分支脚本下载固定摘要输入，重建 boot 后验证：

- 原救砖包大小、SHA-256、AML v2 容器和 CRC；
- boot 内核与原 ramdisk 内容不变，仅新增首次启动 overlay；
- 只修改 boot_a、对应 VERIFY 和容器 CRC，其余字节不变；
- 全部分区 VERIFY、IMG / ZIP SHA-256。

成品 ZIP 包含固定名称 IMG、BUILD.json、SHA256SUMS、许可附件和中文刷机说明。公共 Release 保存成品，不依赖 Actions 临时产物保留期。相同配置与相同构建配方复用已校验成品：配方摘要只覆盖构建相关文件（固定输入清单、组件与脚本模板），不含提交 SHA，纯文档或网页改动不重建。编辑 Issue 不会更改创建时快照；维护者可通过工作流的 `issue_number` 显式重试当前请求内容。

```sh
python3 -m unittest discover -s tests -v
npm test
npm run check
python3 -m http.server 8765 --directory web
```

Linux x86_64 可本地构建（约需 12 GB 可用磁盘，无需 Android SDK）：

```sh
mkdir -p work
cp examples/default.json work/config.json
python3 scripts/build.py --config work/config.json --work work/build --output dist
```

运行器使用官方 Magisk 27 APK 内的静态 `magiskboot`，无需额外下载安装来历不明的固件工具。不要对成品运行首次启动脚本；这些脚本只供该板型开机执行。
